# Event System — code map

A file-by-file reference for this codebase, meant purely for navigation: "which file do I edit to change X." It doesn't explain *why* things are built the way they are — for that, see `/CLAUDE.md`'s running history, which is the actual source of truth for design decisions. This doc can go stale as the app changes; if something here looks wrong, trust the code over this file.

**Stack in one line**: Next.js 16 App Router (TypeScript, RSC), Prisma 7 + SQLite, NextAuth v5, Tailwind v4. Server Actions handle writes, plain query functions handle reads, everything flows through one RBAC function in `authz.ts`.

## 1. Pages & routes (`src/app`)

Files in this tree are Next.js App Router conventions: `page.tsx` is a route's screen, `layout.tsx` wraps its children (and any nested routes) with shared chrome, and `route.ts`/`route.tsx` under `api/` are plain HTTP handlers (no JSX response, just `Response`/`Request`). The `(app)` folder is a *route group* — it doesn't appear in the URL — that wraps every authenticated screen with the shared `Sidebar` nav and the in-app confirm/notify dialog provider; `login/` and the bare root `page.tsx` sit outside it, unauthenticated.

### Login & root

- **`app/layout.tsx`** — The root layout wrapping literally every route including `/login`. Loads the self-hosted Neue Regrade variable font, fetches `CompanySettings` and injects the 6 customizable theme colors (`getAppColors`/`colorsToCssVars` from `lib/theme.ts`) as inline CSS custom properties on `<html>`, and sets `<html lang>` from `CompanySettings.locale`. This is the single mechanism that makes the Settings → App settings color/language customization repaint the whole app, login page included. Also carries `export const dynamic = "force-dynamic"` — every route already depends on the session/DB per request, and this stops `next build` from trying to statically prerender `/_not-found` (which would run this layout's DB call at build time — fatal on a host like Railway where a volume-backed database only exists once the runtime container starts).
- **`app/page.tsx`** — The bare `/` route. No UI of its own — just checks the session and redirects to `/dashboard` or `/login`.
- **`app/login/page.tsx`** — The login screen. Re-checks a stale session cookie's `active` flag before bouncing an already-logged-in user onward (a deactivated user's cookie isn't proactively cleared elsewhere, so this guards against a redirect loop). Renders the "EVENT SYSTEM" wordmark and hands off to `LoginForm`.
- **`app/login/LoginForm.tsx`** — Client component, the actual email/password form. Calls `loginAction` (`lib/actions/auth.ts`) via `useActionState`, uses the shared `PasswordInput` (hold-to-reveal) component, and has a permanently-disabled "Continue with Google" button as a placeholder for the not-yet-built OAuth provider.

### `(app)` layout

- **`(app)/layout.tsx`** — Wraps every authenticated screen. Calls `requireUser()` (the RBAC/session gate — see `lib/authz.ts`), fetches the current running timer for the sidebar's live display, and renders `Sidebar` + `ConfirmDialogProvider` (the app-wide in-app confirm()/notify() replacement) around `{children}`.

### Dashboard

- **`(app)/dashboard/page.tsx`** — The single most complex page file in the app. Three sub-views via `?view=list|timeline|calendar` (shared `SegmentedTabs`): **List** (default) shows three "Needs attention" tiles (overdue invoices, quotes awaiting a response, events ready to invoice — red/warning styling when something needs action), a grid of upcoming-event cards, latest expenses, and a monthly income/expense bar chart. **Timeline** (`TimelineList`, defined inline in this same file) is a chronological build/start/milestone feed grouped by day — this view's design is original to this project, not from any wireframe. **Calendar** delegates to the shared `WeekCalendar`/`WeekNav` components. Pulls data from `getDashboardData`/`getDashboardTimeline` (`lib/queries/dashboard.ts`) and `getWeekCalendarData` (`lib/queries/calendar.ts`).

### Events

- **`(app)/events/page.tsx`** — Events list. Two sub-views via `?view=table|calendar` (`SegmentedTabs` + `WeekNav`/`WeekCalendar` for calendar). Table view has status/client/place filter selects plus a text search, a "jump to today" anchor link, and gates the "New event" button behind `canCreateEvent`. Uses `getEventList`/`getWeekCalendarData`.
- **`(app)/events/new/page.tsx`** — Thin: gates on `canCreateEvent`, fetches client options for the picker, and renders `EventForm` with empty defaults.
- **`(app)/events/[id]/layout.tsx`** — Wraps all `/events/[id]/*` tab routes. Renders the sticky header (event number/title/company/dates, status pill, Edit link gated by `canEditEvent`, and `DeleteEventButton` gated by `isAdmin`) plus `EventTabs` (the Overview/Milestones/Quotes/Expenses/Time/Files tab strip). `children` is whichever sub-tab page is active.
- **`(app)/events/[id]/page.tsx`** — The Overview tab. A two-column layout: left side is brief/dates/venues/client-contacts/company-info/next-milestones (all read-only text); right side is four glass cards — Budget vs actual (quoted value vs. expenses vs. invoiced, computed inline), Time logged (with an inline "Start timer" button wired to `startTimerAction`, or a disabled state if a timer is already running elsewhere), Documents (lists quotes/invoices with a shortcut to `/finance/quotes/new?eventId=`), and Team (member avatar initials).
- **`(app)/events/[id]/edit/page.tsx`** — Gates on `canEditEvent`, loads the full event detail plus client options, renders `EventForm` pre-filled.
- **`(app)/events/[id]/expenses/page.tsx`** — Expenses tab: read-only list of the event's expenses (date/category/paid-by/amount) with a total. No add/edit here — that only happens from Finance → Expenses.
- **`(app)/events/[id]/files/page.tsx`** — Placeholder tab ("not built yet" copy). No file-upload feature exists for events yet.
- **`(app)/events/[id]/milestones/page.tsx`** — Milestones tab: lists milestones with delete (via `ConfirmDeleteButton`, gated on edit permission) and an inline add-milestone form (`addMilestoneAction`). This is the only place milestones are managed — the same data also feeds the Dashboard/Events calendar views.
- **`(app)/events/[id]/quotes/page.tsx`** — Quotes & invoices tab: two simple linked lists (quote/invoice number, date, total, status pill), each row linking to that document's own Finance detail page.
- **`(app)/events/[id]/time/page.tsx`** — Time tab: total logged minutes, a by-person breakdown, and a full entry list. `liveMinutes()` (defined in this file) computes a still-ticking running entry's current duration on the fly rather than showing a stale stored value.

### Clients

- **`(app)/clients/page.tsx`** — List with a name search box; columns are company/IČO/contact count/event count/total charged. "New client" gated by `canManageClients`.
- **`(app)/clients/new/page.tsx`** — Thin: gates on `canManageClients`, renders `ClientForm` with empty defaults (structured address fields all blank).
- **`(app)/clients/[id]/page.tsx`** — Detail page: left column is the linked-events list (title/dates/price/status, each linking to the event) and the contacts list (with per-contact remove via `deleteClientContactAction`, and `AddContactButton`/`AddContactModal` for adding one); right column is one glass card with address/IČO/DIČ/invoicing email/note/total-charged, and (Admin-only) a full-width delete button.
- **`(app)/clients/[id]/edit/page.tsx`** — Gates on `canManageClients`, loads the raw `Client` row directly via Prisma (not through a query helper), renders `ClientForm` pre-filled.

### Finance

- **`(app)/finance/page.tsx`** — Bare redirect to `/finance/quotes`. Not a real screen.
- **`(app)/finance/layout.tsx`** — Wraps all `/finance/*` routes. Gates the whole section on `canViewFinance` (shows a plain "no access" message otherwise), fetches open quote/invoice/expense counts for the header, and renders `FinanceTabs` (the Quotes/Invoices/Expenses/Reports tab strip — a glass-pill `SegmentedTabs`).
- **`(app)/finance/expenses/page.tsx`** — List with event/category filter selects. Columns: date/category/event/paid-by/amount/receipt-link/edit-link(per-row, gated by `canEditExpense`)/delete(Admin-only, `ConfirmDeleteButton`). Uses `getExpenseList`.
- **`(app)/finance/expenses/new/page.tsx`** — Builds the payer dropdown (self-only, or self+card-holders if `canPickOtherPayer`) and event list, renders `ExpenseForm`.
- **`(app)/finance/expenses/[id]/edit/page.tsx`** — Loads the raw expense via Prisma, gates on `canEditExpense(user, expense.paidById)`, renders `ExpenseForm` pre-filled including existing receipt info.
- **`(app)/finance/invoices/page.tsx`** — List with a KPI strip (`KpiCell`, defined inline: issued-unpaid/overdue/due-in-7-days/paid-this-month, from `getInvoiceKpis`) and status "bucket" filter pills (All/Issued/Paid/Overdue/Partly paid) plus an event filter. Each row has a `DownloadPdfButton` (EN/CZ chooser). Admin/Accountant get an "Export accounting CSV" link to `/api/finance/invoices/export`.
- **`(app)/finance/invoices/new/page.tsx`** — Gates on `canManageFinance`. If any quotes are `ACCEPTED` with no invoice yet, shows a "From an accepted quote" box with one-click convert (`convertQuoteToInvoiceAction`) above the blank `InvoiceForm`.
- **`(app)/finance/invoices/[id]/page.tsx`** — The invoice detail page — one of the largest files in the app. Left: a live on-screen preview mirroring the generated PDF layout (line items grouped by category, base/VAT/discount/total). Right column: four-to-five glass cards — Payment state (progress bar, overdue styling), Record payment (form, only shown while a balance remains), Linked (event/quote/expenses links), History (the `InvoiceEvent` action log), and (Admin-only) Delete. Header actions: Download PDF, Mark as paid / Undo mark as paid (the undo button only appears when `realAmountPaid < total`, i.e. there's a genuinely artificial "mark as paid" to undo). Uses `getInvoiceDetail`.
- **`(app)/finance/quotes/page.tsx`** — List with status/event/year filters. Per-row action area varies by status: Convert-to-invoice (ACCEPTED + no invoice yet), a link to the resulting invoice (ACCEPTED + invoiced), Edit (DRAFT), "Create new" duplicate (DECLINED, via `duplicateQuoteAction`), or a disabled "Remind client" placeholder otherwise. Admin gets an inline delete button per row.
- **`(app)/finance/quotes/new/page.tsx`** — Gates on `canManageFinance`. Accepts `?eventId=` (used by the event detail page's "New quote for this event" shortcut) to pre-select `EventForm`'s event picker via `QuoteForm`'s `initialEventId` prop.
- **`(app)/finance/quotes/[id]/page.tsx`** — Quote detail page, structurally parallel to the invoice detail page (on-screen PDF-mirroring preview + sidebar cards: Status/expired-check, Linked, Created-by, Admin-only Delete). Status-transition buttons appear conditionally: Mark accepted/declined (SENT), Convert to invoice (ACCEPTED, not yet invoiced), Create duplicate (DECLINED).
- **`(app)/finance/quotes/[id]/edit/page.tsx`** — Only reachable/functional while `status === "DRAFT"` (shows an explanatory message otherwise) and gated on `canManageFinance`. Renders `QuoteForm` pre-filled.
- **`(app)/finance/reports/page.tsx`** — Three tabs via plain `Link`s: Overview (default — monthly income/expense bar chart + breakdown table + top categories), By event, By category. Year navigation via prev/next arrows. CSV export link to `/api/finance/reports/export` and a `PrintButton` (browser print, CSS-hidden toolbar). Uses `getReports`.

### Settings

- **`(app)/settings/page.tsx`** — Four tabs via `?tab=company|users|templates|appSettings`, gated per-tab on `canManageCompanySettings`/`canManageUsers` (falls back to a plain "signed in as" info box if the user has neither). Fetches users, `CompanySettings`, custom roles (with assigned-user counts), and item categories, then delegates entirely to `CompanySettingsForm`, `CreateUserForm`+`UsersTable`+`RoleReferenceTable` (the last one absorbs what used to be a standalone custom-roles tab — it lists built-in roles' access read-only and lets Admin create/edit/delete custom ones inline), `CategoriesTab`, and `AppSettingsForm`.
- **`(app)/settings/users/[id]/edit/page.tsx`** — Gates on `canManageUsers`, loads the target user plus the custom-role list, renders `EditUserForm` (name/email/phone/card-holder/role editing, plus the deactivate/reactivate action — all disabled when editing your own account).

### Time tracker

- **`(app)/time-tracker/page.tsx`** — Bare redirect to `/time-tracker/tracking`.
- **`(app)/time-tracker/layout.tsx`** — Wraps `/time-tracker/*`, renders the sticky header + `TimeTrackerTabs` (Tracking/Overview).
- **`(app)/time-tracker/tracking/page.tsx`** — The busiest time-tracker file. Hero area is either the running-timer box (`RunningTimerBox`, always wins if a timer is active) or a Timer/Manual `SegmentedTabs` toggle switching between `RunningTimerBox`'s idle "start" form and `ManualEntryForm`. Below that, a List/Calendar `SegmentedTabs` switch: **List** (`ListView`, defined inline) has its own Day/Week/Month period switch with prev/next/Today navigation (`stepDate`/`periodLabel` from `lib/period-nav.ts`), an entry table with per-row Edit/Delete, and a sidebar totals card; **Calendar** delegates to `TimeTrackerCalendar` + `WeekNav`. Uses `getMyTimeTrackerData`/`getTimeTrackerCalendarData`.
- **`(app)/time-tracker/overview/page.tsx`** — The team time-overview screen (replaced the old "Compare events" feature). Day/Week/Month period switch plus a People multi-select (chip-to-remove / +name-to-add, URL-param driven via `?users=`). Day view renders per-person cards with an event breakdown (`DayBreakdown`, inline); Week/Month render a person-by-bucket table (`BucketTable`, inline). Uses `getOverviewData`/`getOverviewUsers`.
- **`(app)/time-tracker/entries/[id]/edit/page.tsx`** — Loads a single `TimeEntry` directly via Prisma (scoped to the current user — no cross-user editing), refuses to edit a still-`running` entry, renders `EditEntryForm` with derived HH:mm start/end strings.

### API routes (`api/`)

- **`api/auth/[...nextauth]/route.ts`** — Just re-exports NextAuth's `GET`/`POST` handlers from `src/auth.ts`. This is the entire wiring for the Credentials-provider login flow.
- **`api/address-search/route.ts`** — Auth-gated proxy to `searchAddresses` (`lib/address-search.ts`, the Photon/OpenStreetMap worldwide address-autocomplete API). Backs `AddressAutocompleteInput`/`StructuredAddressInput`.
- **`api/ares/[ico]/route.ts`** — Auth-gated proxy to `lookupCompanyByIco` (`lib/ares.ts`, the Czech ARES business-registry API). Backs every "Load from ARES" button (Event form, Client form, Company settings).
- **`api/finance/invoices/export/route.ts`** — Generates an accounting CSV of every invoice the current user can see (number/event/client/issued/due/total/paid/status), via `toCsv`/`csvResponse` (`lib/csv.ts`).
- **`api/finance/reports/export/route.ts`** — Generates a monthly income/expense/balance CSV for the given `?year=`, same underlying data as the Reports page's Overview tab.
- **`api/invoices/[id]/pdf/route.tsx`** — Generates the actual invoice PDF via `@react-pdf/renderer`'s `renderToBuffer`. Assembles the Czech "QR Platba" QR code (skipped for non-CZK invoices — the SPD payment-string spec is CZK-only), the base64 company logo (`readLogoAsDataUrl`), and renders `InvoicePdf`. Respects `?lang=cs|en`. Returns `Content-Type: application/pdf`.
- **`api/quotes/[id]/pdf/route.tsx`** — Same pattern as the invoice PDF route but for `QuotePdf` — no QR code or payment logic since a quote isn't a payable document.
- **`api/uploads/logo/[filename]/route.ts`** — Serves a company logo file from disk. Only checks the requester is logged in (no per-owner check — a logo is shared branding, not per-user data) and that the filename matches the current `CompanySettings.logoPath`.
- **`api/uploads/receipts/[filename]/route.ts`** — Serves an expense receipt file from disk. Unlike the logo route, this one does check per-owner access — the filename must match a receipt on an expense the requesting user is actually allowed to see (`expenseWhereForUser`), returning 404 otherwise even if the file exists.

## 2. Shared UI components (`src/components`)

These are the React components pages assemble — noted as Client (`"use client"`) or Server Components, with cross-references where one is reused by multiple screens.

### Cross-cutting / top-level

- **`components/AddContactModal.tsx`** — Client. Exports `AddContactButton` (a small trigger) and the modal itself, which opens on click and posts to `addClientContactAction`. Used on the Client detail page to add a contact person to a client. Auto-closes via a `useEffect` watching `state.success` from `useActionState` — the same self-closing pattern used by `QuickCreateEventModal`.
- **`components/BackLink.tsx`** — Server Component. Trivial "← back" link styled for detail-page headers (bigger/more visible than the earlier near-invisible breadcrumb).
- **`components/ClientForm.tsx`** — Client. The create/edit form for a `Client` (used by both `/clients/new` and `/clients/[id]/edit`). Has ARES "Load from IČO" lookup (fills name/DIČ/structured address via `StructuredAddressInput`), invoicing email, and a note field.
- **`components/ClientPicker.tsx`** — Client. A plain `<select>` of existing clients, no "create new" option (that was deliberately removed). `onSelect` hands the full client record back to the parent (`EventForm`) so it can autofill company fields.
- **`components/ComingSoon.tsx`** — Server Component. Generic placeholder screen (title + description) — worth checking whether anything still renders it, since every nav item is live now.
- **`components/DeleteEventButton.tsx`** — Client. Event-specific hard-delete button (not the generic `ConfirmDeleteButton`) because it needs pre-check logic: if the event has expenses or invoices, it shows a `notify()` explaining why deletion is blocked and never reaches the confirm step; otherwise shows the normal `confirm()` → delete flow. Plain `button onClick` + `startTransition` calling the server action directly (not a `<form action>`) — see `ui/ConfirmDeleteButton.tsx` below for why.
- **`components/EventForm.tsx`** — Client. The big create/edit Event form: title/brief/status/quoted value, build/start/end/strike dates (with "moving start date pulls end date along" logic), repeatable venue rows, repeatable contact-person rows, `ClientPicker` integration (autofills company fields on select), and ARES lookup for company IČO/name/address/DIČ.
- **`components/EventPicker.tsx`** — Client. Reusable `<select>` of events plus a "+ New event" button that opens `QuickCreateEventModal` inline — used by Quote/Invoice/Expense/time-entry forms wherever an event needs picking. Supports an `extraOption` (used by Expenses for "Company overhead — not tied to an event").
- **`components/EventTabs.tsx`** — Client (`usePathname` for active-tab highlighting). The tab strip on an event detail page: Overview/Milestones/Expenses/Time/Quotes & Invoices/Files, with counts baked into some labels. Plain underline-tab style, not the glass-pill `SegmentedTabs`.
- **`components/QuickCreateEventModal.tsx`** — Client. Minimal event-creation modal (title/client contact/company/dates only) invoked from `EventPicker` so a user doesn't have to leave a Quote/Invoice/Expense form to create the event it belongs to. Calls `quickCreateEventAction`.
- **`components/Sidebar.tsx`** — Client. The main nav — Dashboard/Clients/Events/Finance/Time tracker, Settings, sign-out, and embeds `TimerWidget`. Floating design (`sticky top-3 ml-3 rounded-2xl`, `.glass-panel` styled) — no pin/unpin toggle (removed).
- **`components/StatusPill.tsx`** — Server Component (pure, no `"use client"`). Exports three pill/tag components: `EventStatusPill`, `QuoteStatusPill`, `InvoiceStatusPill`. Encodes the app's status→color mapping (positive=teal/warning=red/neutral=gray) — **this is the file to edit if a status's color or wording needs to change.** `InvoiceStatusPill` derives "overdue"/"due soon"/"due in N days" from `dueDate`/`paidAt` rather than a stored enum value.
- **`components/TimeTrackerTabs.tsx`** — Client. Two-tab strip (Tracking / Overview) for the Time tracker section.
- **`components/TimerWidget.tsx`** — Client. The small sidebar card showing either "no timer running" (with a link to start one) or a live-ticking elapsed-time readout with a Stop button — embedded inside `Sidebar.tsx`.

### Calendar (`components/calendar/`)

- **`calendar/WeekCalendar.tsx`** — Server Component. Renders one week as an hourly grid: an "all-day" bar row for multi-day prep/build vs. main event-day spans, a timed grid below for milestones (side-by-side columns on overlap via `assignColumns` from `lib/calendar.ts`), plus a "this week's events" legend list. Used by the Dashboard and Events Calendar views.
- **`calendar/WeekNav.tsx`** — Server Component. Prev/Today/Next week navigation links; takes an `hrefFor(weekIso)` callback so the caller controls the URL shape.

### Finance forms (`components/finance/`)

- **`finance/DownloadPdfButton.tsx`** — Client. Turns a plain "Download PDF" link into an in-app EN/CZ dropdown (not a native `prompt()`) — used on invoice/quote list rows and detail pages.
- **`finance/ExpenseForm.tsx`** — Client. Create/edit form for an `Expense`: receipt upload (via `ReceiptInput`), amount, date, "paid by" (defaults to current user; card holders/Admin/Accountant/Producer get a dropdown of all card holders), category, event picker (with the "company overhead" no-event option), note. Has a "Save and add another" button for rapid entry.
- **`finance/FinanceTabs.tsx`** — Client. Quotes/Invoices/Expenses/Reports tab strip with counts, used under `/finance/*`. **Uses the shared glass-pill `SegmentedTabs`** (not a hand-rolled underline tab — this was changed to match the rest of the app's redesign; `EventTabs`/the Settings tab bar are still plain underline tabs by contrast).
- **`finance/InvoiceForm.tsx`** — Client. Create form for a blank `Invoice`: event picker (auto-fills one line item from the event's title + quoted value the first time an event is picked — only while items are still untouched), due date, currency, `LineItemsFields`, hide-item-prices checkbox, and the discount fields (NONE/PERCENT/FIXED + value).
- **`finance/LineItemsFields.tsx`** — Client. **The shared repeatable line-items grid used by both `QuoteForm` and `InvoiceForm`.** Controlled by the parent (not internal state) since `InvoiceForm` needs to reach in and auto-fill it. Handles add/remove/reorder (▲/▼ swap) rows, a category `<input list>` backed by a shared `<datalist>`, and computes Base/VAT/Total. **Non-obvious gotcha**: the header row and item rows must stay one single CSS Grid (via `Fragment` per row), not separate per-row grids sharing a template string — two independent grids with the same `grid-cols` string can still resolve different actual pixel widths per column when their content differs (caused a real column-misalignment bug once).
- **`finance/PrintButton.tsx`** — Client. Trivial `window.print()` trigger button, hidden in print view via `print:hidden`.
- **`finance/QuoteForm.tsx`** — Client. Create/edit form for a `Quote`: event picker (create-only — hidden when editing), status, currency, valid-until date (with a conflict warning if it lands within a week of the event's start date), `LineItemsFields`, hide-item-prices checkbox. Accepts `initialEventId` for the "New quote for this event" shortcut from the event detail page.
- **`finance/ReceiptInput.tsx`** — Client. Drag-and-drop / click-to-browse file input for expense receipts (image or PDF, `capture="environment"` for mobile camera), with an existing-receipt link + "remove" checkbox when editing.

### Settings (`components/settings/`)

- **`settings/AppSettingsForm.tsx`** — Client. The "App settings" tab form: 6 color swatch+hex pairs (background/surface/text & borders/accent/positive/warning, each with a hint line), a live 6-chip preview, "Reset to defaults" (pulls from `lib/theme.ts`'s `DEFAULT_COLORS`), and the English/Czech language radio. Submits to `updateAppSettingsAction`. **Edit this file to change the color-customization or language-switch UI itself**; edit `lib/theme.ts`/`lib/dictionary.ts` to change the underlying values/translations.
- **`settings/CategoriesTab.tsx`** — Client. CRUD list for the org's default quote/invoice line-item categories (add/rename/delete, delete gated by an in-app confirm). This is the component behind the Settings → Templates tab.
- **`settings/CompanySettingsForm.tsx`** — Client. The Company tab form: IČO+ARES lookup, name, address (`AddressAutocompleteInput`), DIČ/VAT-payer checkbox, bank account (IBAN, feeds the invoice QR code), logo upload with live preview, invoice due-days default, and a read-only "numbering scheme" note. Also renders a static "Connected accounts" panel (Google Workspace/Calendar — both honestly shown "Not connected"; ARES shown "Active").
- **`settings/CreateUserForm.tsx`** — Client. Inline form (name/email/role/company-card checkbox) at the top of Users & roles to create a new account; shows the generated one-time password in the success message.
- **`settings/EditUserForm.tsx`** — Client. The `/settings/users/[id]/edit` page's form: name/email/phone/role/card-holder, plus (below a divider) a "generate new password" button and a deactivate/reactivate button — both hidden when editing your own account. The deactivate button uses the onClick+`startTransition` pattern (not `<form action>`) for the same race-avoidance reason as `ConfirmDeleteButton`.
- **`settings/RoleReferenceTable.tsx`** — Client. The "What each role can reach" table on Settings — shows the 4 built-in roles' access as fixed read-only text, plus any custom roles with inline Edit/Delete and an embedded create/edit form (`RoleForm`, four `AccessField` dropdowns for Events/Finance/Expenses/Settings tiers). **This is where custom-role CRUD UI lives** — it absorbed what used to be a standalone `RolesTab.tsx` component (deleted).
- **`settings/RoleSelect.tsx`** — Server Component. A `<select>` used by both `CreateUserForm` and `EditUserForm` — built-in roles in one `<optgroup>`, custom roles in another; value format is `"ROLE:ADMIN"` or `"CUSTOM:<id>"`, parsed server-side in `lib/actions/settings.ts`'s `parseRoleSelection`.
- **`settings/UsersTable.tsx`** — Client (needs `useActionState` for the inline reset-password button). The Users & roles list: name/account/role/company-card toggle/last-seen/actions per row, with inactive users dimmed and tagged.

### Time tracker (`components/timetracker/`)

- **`timetracker/DateJumpPicker.tsx`** — Client. A native `<input type="date">` used purely to jump the Overview/Tracking page's period anchor via `router.push` — its own browser popup is intentionally the "pick via calendar" affordance (no custom calendar widget).
- **`timetracker/DeleteEntryButton.tsx`** — Client. Confirm-gated delete for a single time entry, same onClick+`startTransition` pattern as `ConfirmDeleteButton`.
- **`timetracker/EditEntryForm.tsx`** — Client. Edit form for one time entry: date, duration (minutes), optional start/end time (recomputes duration), phase, description.
- **`timetracker/ManualEntryForm.tsx`** — Client. The "Manual" mode form in Tracking's hero spot: event, date, phase, start/end time OR a plain duration field, description.
- **`timetracker/RunningTimerBox.tsx`** — Client. Renders the Tracking page's hero card — the running-timer/start-timer state that always takes over the hero spot regardless of the Timer/Manual toggle. Idle state is a "Start a timer" form (event/phase/description selects, submits to `startTimerAction`). Running state shows a live-ticking elapsed-time readout (`formatElapsed`, `HH:MM:SS`) that updates every second via `setInterval`, a description field editable inline (submits with the stop form), a Stop button (`stopTimerAction`), and a `SwitchEvent` sub-component — a `<details>`/`<summary>` dropdown letting you start a new timer on a different event without an extra click to stop the current one first. - **`timetracker/TimeTrackerCalendar.tsx`** — Server Component. Hourly weekly grid for the Time tracker's Calendar view — same architecture family as `WeekCalendar.tsx` (positioned blocks + `assignColumns` for overlaps) but for time entries: scheduled entries (with a real `startedAt`) become positioned blocks, duration-only entries render as chips in an "Unscheduled" lane above the grid.

### Generic UI primitives (`components/ui/`)

- **`ui/AddressAutocompleteInput.tsx`** — Client. Single free-text address field with a debounced (300ms) Photon/OpenStreetMap worldwide autocomplete dropdown. Used by `EventForm` (company address) and `CompanySettingsForm` — the single-string counterpart to `StructuredAddressInput`.
- **`ui/CancelLink.tsx`** — Server Component. Trivial styled `<Link>` used as the "Cancel" button on essentially every create/edit form.
- **`ui/ConfirmDeleteButton.tsx`** — Client. **The shared confirm-gated delete button** used by milestones/quotes/invoices/expenses/categories. Deliberately a plain `button onClick` + `startTransition(() => action(formData))`, never a `<form action>` + `onSubmit`-preventDefault — a real historical bug had that pattern race (React 19's internal form-action dispatch could win against the `onSubmit` handler's `preventDefault()`, so delete could fire even after Cancel). **Any new destructive button in this app should follow this same pattern, not the form+onSubmit one.**
- **`ui/ConfirmDialogProvider.tsx`** — Client. Context provider (mounted once in the app layout) exposing `confirm(message, opts)` and `notify(message, opts)` as Promise-based, in-app-styled replacements for `window.confirm`/`window.alert`. **Edit this file to change the confirm/notify dialog's look or button layout app-wide.** Renders Cancel as the filled/solid button and Confirm as the outlined one deliberately — making the safe choice visually louder since every use here is for a destructive action.
- **`ui/Modal.tsx`** — Client. Generic centered modal shell (title bar + close button + Escape-to-close + click-outside) used by `AddContactModal`, `QuickCreateEventModal`, and others that need a modal.
- **`ui/PasswordInput.tsx`** — Client. Password field with a **hold-to-reveal** (not click-toggle) eye icon — press and hold to see the password, release to hide it. Used on the login form.
- **`ui/SegmentedTabs.tsx`** — Client. The glass-pill switcher with a sliding highlight thumb (tracks real measured widths via `getBoundingClientRect`, not assumed-equal widths). Takes `options: {value, href, label}[]` — each option is a real `Link`, so it works for both same-page view toggles (Dashboard's List/Timeline/Calendar) and cross-route section nav (Finance's Quotes/Invoices/Expenses/Reports).
- **`ui/StructuredAddressInput.tsx`** — Client. Four-field address input (street/city/postCode/state) with the same Photon-backed autocomplete on the street field as `AddressAutocompleteInput`, but fills all four fields at once on selection. Currently used only by `ClientForm`.

## 3. Core logic (`src/lib`)

Four kinds of file live here: **Server Actions** (`lib/actions/`, `"use server"` functions that forms in `src/components/` submit to — these do the writes, with permission checks and redirects), **queries** (`lib/queries/`, read-side data-fetching used by `page.tsx` Server Components, several wrapped in React's `cache()` so one request's duplicate calls hit the DB once), **PDF generation** (`lib/pdf/`, server-side `@react-pdf/renderer` templates rendered inside the two PDF route handlers), and general **utilities/business-logic helpers** at the top level of `lib/`.

### Server Actions (`lib/actions/`)

- **`lib/actions/auth.ts`** — `signOutAction`, `loginAction` (credentials sign-in via NextAuth's `signIn("credentials", …)`, returns a translated "Invalid credentials" error on `AuthError` rather than throwing).
- **`lib/actions/categories.ts`** — CRUD for the org-wide default line-item categories shown in Settings → Templates: `getItemCategories`, `createCategoryAction`, `renameCategoryAction`, `deleteCategoryAction`. Gated by `canManageCompanySettings`. Note: `QuoteItem`/`InvoiceItem.category` is a plain string, not a foreign key here — deleting a category never touches items already tagged with it.
- **`lib/actions/clients.ts`** — `createClientAction`, `updateClientAction`, `deleteClientAction` (Admin-only), plus the contact sub-actions `addClientContactAction`/`deleteClientContactAction`. Also exports two helpers *called from* `lib/actions/events.ts` rather than from a form directly: `resolveClientId()` (auto-creates or reuses a `Client` by IČO-or-name match when an event is saved without an explicit client picked) and `syncClientContacts()` (copies an event's contact people onto the resolved client, deduped by email-or-name, independent copies with no FK back to the source).
- **`lib/actions/events.ts`** — `createEventAction`, `updateEventAction`, `deleteEventAction` (Admin-only; **refuses to delete if the event has any expenses or invoices** — silently no-ops, since the real gate is client-side in `DeleteEventButton`), `quickCreateEventAction` (minimal event for the "+ New event" modal, returns the created event instead of redirecting), `addMilestoneAction`, `deleteMilestoneAction`. Assigns the event's `number` via `nextEventNumber()` from `document-number.ts`.
- **`lib/actions/finance.ts`** — the biggest action file. Quotes: `createQuoteAction`, `updateQuoteAction` (DRAFT-only), `updateQuoteStatusAction` (SENT→ACCEPTED/DECLINED only), `duplicateQuoteAction` (DECLINED→fresh DRAFT copy), `deleteQuoteAction` (Admin-only), `convertQuoteToInvoiceAction`. Invoices: `createInvoiceAction`, `recordPaymentAction`, `markInvoicePaidAction`, `revertInvoicePaidAction` (recomputes `amountPaid` from real `Payment` rows so it only ever undoes the *artificial* mark-as-paid shortcut, never a real payment), `deleteInvoiceAction` (Admin-only). Expenses: `createExpenseAction`, `updateExpenseAction`, `deleteExpenseAction` (Admin-only, also unlinks the receipt file). Also has the two pure-math helpers `itemsTotal()` and `applyDiscount()` — **the discount is applied to the pre-VAT base and VAT is recomputed on the discounted amount**, not a flat cut off the total; read this function before touching discount math.
- **`lib/actions/settings.ts`** — user management (`createUserAction`, `resetPasswordAction`, `updateUserInfoAction` — silently skips the role/customRoleId write when editing your own account, `deactivateUserAction`/`reactivateUserAction`, `toggleCardHolderAction`), custom roles (`createCustomRoleAction`/`updateCustomRoleAction`/`deleteCustomRoleAction` — delete fails with a message if any user is still assigned), and app-wide config (`updateCompanySettingsAction`, `updateAppSettingsAction` — the latter validates all 6 hex colors + locale and revalidates `"/", "layout"` since colors/locale affect every route, not just `/settings`).
- **`lib/actions/timetracker.ts`** — `startTimerAction`/`stopTimerAction` (starting one always stops any other running timer first — "one running timer" is enforced here, not by a DB constraint), `addManualEntryAction`/`updateManualEntryAction`/`deleteTimeEntryAction`. Internal helper `computeMinutesAndTimes()` is worth knowing: a manual entry with real start+end times gets `startedAt`/`endedAt` persisted (needed so the Calendar view has something to position); a duration-only entry gets neither.

### Data queries (`lib/queries/`)

- **`lib/queries/calendar.ts`** — `getWeekCalendarData()`, used by the Dashboard/Events week calendars. Matches events whose build→strike span overlaps the week **or** that have a milestone in the week (the latter was a real bug fix for milestones happening well before an event's on-site dates).
- **`lib/queries/clients.ts`** — `getClientList`, `getClientDetail` (cached), `getClientOptions` (deliberately unscoped by `eventWhereForUser` — picking a client for a new event isn't the same permission as seeing their events; returns the full address/IČO/DIČ fields so `ClientPicker` can autofill them).
- **`lib/queries/dashboard.ts`** — `getDashboardData()` (the "Needs attention" tiles: overdue invoices, waiting quotes, events to invoice, plus upcoming events / latest expenses / the monthly balance chart data) and `getDashboardTimeline()` (the chronological build/start/milestone feed for the Timeline view, next 60 days).
- **`lib/queries/events.ts`** — `getEventList()` (with search/status/client/place filters) and `getEventDetail()` (cached; the one big include pulling venues/milestones/members/expenses/timeEntries/quotes/invoices/contacts for the tabbed event detail page).
- **`lib/queries/finance.ts`** — the largest queries file: `isOverdue()`/`overdueDays()` (the canonical "is this invoice overdue" check — **`InvoiceStatus` has no stored OVERDUE value**, it's always derived from `dueDate` vs `now`), `getQuoteList`/`getQuoteDetail`, `getInvoiceList`/`getInvoiceKpis`/`getInvoiceDetail`, `getExpenseList`, `getReports()` (by-month/by-event/by-category breakdowns for the Reports page), and `getCompanySettings()` (reads the `CompanySettings` singleton — also used by `theme.ts`/`i18n.ts` for the app-wide color/locale injection).
- **`lib/queries/timetracker.ts`** — `getRunningTimer()`, `rangeStart`/`rangeEnd` (period→date-range math shared by Tracking and Overview), `getMyTimeTrackerData()`, `getTimeTrackerCalendarData()`, and the Overview screen's `getOverviewUsers()`/`overviewBuckets()`/`getOverviewData()` (bucketing: one "Total" bucket for day view, one per calendar day for week view, one per week clipped to month boundaries for month view).

### PDF generation (`lib/pdf/`)

- **`lib/pdf/shared.tsx`** — shared `StyleSheet`, `money()`/`pdfDate()` formatters, and **`registerAppFont()`** — the single most important function to understand before touching PDF code. It registers the Neue Regrade TTF (needed because the standard Helvetica font has no glyphs for Czech diacritics ě/ř/ů/ď/ť/ň) under a **freshly-randomized family name on every call**, not once at module scope — `@react-pdf/font`'s internal `FontStore` caches glyph-subsetting state per family name for the process lifetime, and reusing a fixed name was found to silently corrupt digit glyphs in whichever PDF rendered second in the same server process. Never register the font under a fixed/module-scope name again.
- **`lib/pdf/i18n.ts`** — `PDF_LABELS` (`en`/`cs`), `pdfLabels(lang)`. **Completely separate from and unrelated to** the app-wide `src/lib/i18n.ts`/`dictionary.ts` — this only controls the language of a *downloaded PDF* (chosen per-download via `DownloadPdfButton`), independent of the live app's UI language.
- **`lib/pdf/InvoicePdf.tsx`** — the invoice PDF template. Renders supplier/customer blocks, the line-item table (grouped by category via `groupItemsByCategory()`, with a `hideItemPrices` mode that drops to description-only + category subtotals), the base/VAT/discount/to-pay summary, and the footer — QR payment code if the invoice is CZK and a bank account is on file, otherwise an explanatory message instead (QR Platba is CZK-only by spec).
- **`lib/pdf/QuotePdf.tsx`** — same shape as `InvoicePdf.tsx` minus payment concerns (no discount, no QR, no variable symbol); footer states the quote's valid-until date instead.

### Utilities & business logic (`lib/`)

- **`lib/access-levels.ts`** — display labels for the four `CustomRole` permission-tier enums (`EventsAccess`/`FinanceAccess`/`ExpensesAccess`/`SettingsAccess`) plus `*_OPTIONS` arrays, consumed by the custom-role form in Settings.
- **`lib/address-search.ts`** — `searchAddresses()`, wraps the free public Photon API (komoot's OpenStreetMap-backed geocoder, no API key) for the worldwide address-autocomplete dropdowns. Returns both a formatted one-line `label` and Photon's structured `street`/`city`/`postCode`/`state` parts.
- **`lib/ares.ts`** — `lookupCompanyByIco()`, wraps the free public Czech ARES business-registry API. `splitAddress()` prefers ARES's pre-split `adresaDorucovaci` object (falls back to reconstructing from the raw `sidlo` fields), and hardcodes `state: "Česká republika"` since every ARES result is a Czech company by definition.
- **`lib/authz.ts`** — **the central RBAC file; read this before touching any permission logic.** Everything routes through one `resolvePermissions(user): Permissions` function that returns the same four-dimension shape (`events`/`finance`/`expenses`/`settings`, each an access-tier enum) whether the user has a built-in `role` (mapped via the `BUILT_IN_PERMISSIONS` table) or an assigned `CustomRole` (used directly) — every other exported check (`canCreateEvent`, `eventWhereForUser`, `canManageFinance`, `canEditExpense`, `canManageUsers`, etc.) reads from that single resolved shape, so built-in and custom roles can never drift out of sync. Also exports `requireUser()` (the auth gate every protected page/action calls first — re-checks `active` against the DB on every call, not just at login, wrapped in `cache()`) and `isAdmin()` (deliberately checks the *literal* built-in Admin role, not a permission tier — a CustomRole with equivalent `ALL_FULL`/`FULL` access never gets the irreversible-delete buttons).
- **`lib/calendar.ts`** — date-math primitives shared by every calendar/period view: `startOfDay`, `addDays`, `mondayOf`, `weekDays`, `isoWeekNumber`, `assignColumns()` (the overlap-column-assignment algorithm shared by `WeekCalendar` and `TimeTrackerCalendar`), and the important pair **`isoDate()`/`parseIsoDate()`** — deliberately not `toISOString().slice(0,10)` / `new Date(dateString)`, which both silently roll the date by one day depending on UTC offset (a real bug hit twice in this project).
- **`lib/csv.ts`** — `toCsv()` (headers+rows → CSV string with proper quoting) and `csvResponse()` (wraps it as a downloadable `Response`), used by the two CSV export API routes.
- **`lib/dictionary.ts`** — the EN/CZ UI-text dictionary powering the whole app's language switch. A large file exporting `type Locale = "en" | "cs"`, `czCount()` (a simple 1/2–4/5+ Czech pluralization bucket, not full grammatical declension), the full `en`/`cs` objects structured as nested namespaces mirroring the app's IA (`nav`, `common`, `dashboard`, `events`, `clients`, `finance`, `timeTracker`, `settings`, `statusEvent`/`statusQuote`/`invoicePill`, `phases`, `expenseCategories`, `accessLevels`, `roles`, etc.), and `getDictionary(locale)`. **Deliberately has zero imports of Prisma or anything server-only** — this is what makes it safe to import directly from Client Components; any dynamic (parameterized) string in here is a plain JS function, which is exactly why a Client Component must call `getDictionary(locale)` itself rather than receive a pre-built dictionary object as a prop from a Server Component (React can't serialize a function across that boundary).
- **`lib/document-number.ts`** — the unified "YY-XXX" numbering scheme. `nextEventNumber()` scans existing numbers for the year and takes the **lowest unused** integer (not `count()+1`), so a deleted event's number becomes reusable. `nextQuoteNumber()`/`nextInvoiceNumber()` don't get independent sequences — they just append `_v2`/`_v3`… once there's more than one document of that type for the same event. `variableSymbolFor()` strips non-digits for the QR payment variable symbol.
- **`lib/expense-categories.ts`** — `EXPENSE_CATEGORY_LABEL` map + `EXPENSE_CATEGORIES` array for the `ExpenseCategory` enum (Food, Grocery, Travel–gas/car/flight/taxi/parking/public-transport/other, Gear, Generic).
- **`lib/format.ts`** — `formatCurrency()` (the `Intl.NumberFormat` currency formatter — this is what actually makes "Kč"/"€"/"$" render at all), `formatDate`/`formatDateRange`/`formatDateTime`, `toDateTimeLocal()`, `formatClientAddress()` (renders a `Client`'s 4 structured address fields as one line), `formatMinutes()`. Deliberately stays en-GB-shaped regardless of app language — only UI *text* is translated, not date/number formatting.
- **`lib/i18n.ts`** — thin, server-only wrapper: re-exports everything from `dictionary.ts` plus adds `getLocale()` (reads `CompanySettings.locale` via Prisma). **Never import this from a Client Component** — it pulls in Prisma/`better-sqlite3`, which breaks the client bundle; Client Components must import from `@/lib/dictionary` directly instead.
- **`lib/line-items.ts`** — `groupItemsByCategory()` and `categoryTotal()`, shared by the on-screen quote/invoice detail pages and both PDF templates so category grouping/subtotals stay visually consistent everywhere.
- **`lib/period-nav.ts`** — `stepDate()`/`periodLabel()`/`periodNounFor()`/`currentPeriodLabel()`, the day/week/month navigation helpers shared by the Time tracker's Tracking and Overview pages.
- **`lib/prisma.ts`** — the singleton Prisma client, using the `better-sqlite3` driver adapter with `DATABASE_URL` (defaults to `file:./dev.db`), cached on `globalThis` in dev to survive hot-reload.
- **`lib/qr-payment.ts`** — `buildQrPaymentString()`, builds the Czech "QR Platba" SPD payment string (`SPD*1.0*ACC:…*AM:…*CC:CZK*X-VS:…*MSG:…`) that gets rendered to a QR PNG for the invoice PDF. Hardcodes `CC:CZK` — this is why non-CZK invoices skip the QR code entirely.
- **`lib/theme.ts`** — `DEFAULT_COLORS` (mirrors `globals.css`'s hardcoded `:root` values exactly), `getAppColors()` (falls back to defaults when `CompanySettings` is null), `colorsToCssVars()` (turns the 6 colors into CSS custom-property overrides that the root `layout.tsx` spreads onto `<html>`'s inline `style`).
- **`lib/time-phases.ts`** — `PHASE_LABEL` map + `PHASES` array for the `TimePhase` enum (Planning/Suppliers/On site/Wrap-up), used by the time tracker's phase picker.
- **`lib/uploads.ts`** — `saveReceipt`/`readReceipt`/`deleteReceipt` and `saveLogo`/`readLogo`/`deleteLogo`/`readLogoAsDataUrl`. Files live on local disk under `DATA_ROOT/uploads/{receipts,logos}`, where `DATA_ROOT` is `process.env.UPLOAD_DIR ?? process.cwd()` — this env var lets a deployed instance (e.g. Railway) redirect uploads onto a mounted persistent volume without changing local-dev behavior. `readLogoAsDataUrl()` returns `null` for SVG since `@react-pdf/renderer`'s `Image` can't render it.

### Hooks (`hooks/`)

## 4. Data model (`prisma/schema.prisma`, seeds)

The database is SQLite (via Prisma 7 + the `better-sqlite3` driver adapter). `prisma/schema.prisma` is the single source of truth for every table — it's unusually well-commented in place, so reading it directly often answers "why does this field exist" faster than this doc can. The generated client lives at `src/generated/prisma/` (gitignored, regenerated via a `postinstall` script) and is imported as `@/generated/prisma/client` / `@/generated/prisma/enums`, not from `node_modules`.

**Core entities and how they connect:**

- **`User`** — an account. Has either a built-in `role` (`ADMIN`/`ACCOUNTANT`/`PRODUCER`/`MEMBER`) or a `customRoleId` pointing at a `CustomRole`; when a custom role is set, `role` just holds an ignored least-privilege (`MEMBER`) fallback — see `authz.ts`'s `resolvePermissions()` for how both paths resolve to the same permission shape. `active: false` blocks login (checked on every request, not just at login) without deleting the account's history. `isCardHolder` gates who can be picked as "paid by" on an expense.
- **`CustomRole`** — an admin-defined role with its own `EventsAccess`/`FinanceAccess`/`ExpensesAccess`/`SettingsAccess` tier, one enum per module, deliberately the same granularity the four built-in roles already use. Edited in Settings → "What each role can reach."
- **`Event`** — the central object everything else hangs off. Has a unique `number` ("YY-XXX", e.g. `26-001` — see `document-number.ts`), an `EventStatus`, its own embedded `companyName`/`companyAddress`/`companyIco`/`companyDic` (still what PDFs/detail pages actually read from), and an optional `clientId` linking it to a real `Client` for the Clients section's rollups. Cascades on delete to `EventMember`, `Venue`, `Milestone`, `EventContact`, `Expense`, `TimeEntry`, `Quote` (and its `QuoteItem`s), `Invoice` (and its items/payments/history).
- **`EventContact`** — one or more contact people per event (replaced the old single `clientName`/`clientPhone`/`clientEmail` fields). Saving an event syncs each contact onto the linked `Client`'s own `ClientContact` list (dedup by email-or-name) — these are independent copies with no FK back to the source, so deleting one side never touches the other.
- **`EventMember`** — join table for which `User`s are assigned to an `Event`; drives the "own/assigned events" visibility tier for Producers and Members.
- **`Venue`**, **`Milestone`** — simple child records of an `Event` (multiple venues; dated milestones shown on the event's Milestones tab and the calendars).
- **`Expense`** — `eventId` is nullable (null = "company overhead," not tied to any event). `receiptPath` is a filename under `web/uploads/receipts/`, served only through an authenticated route that checks the requester actually has access to the parent expense/event.
- **`TimeEntry`** — a running timer *is* a row with `running: true` and `startedAt` set; stopping fills in `endedAt`/`minutes`. Only one running entry per user is enforced at the application level (the start-action stops any existing one first), not by a DB constraint. `TimePhase` (Planning/Suppliers/On site/Wrap-up) powers the Overview screen's breakdowns.
- **`Quote`** / **`QuoteItem`** and **`Invoice`** / **`InvoiceItem`** — `Quote.status` flows `DRAFT → SENT → ACCEPTED/DECLINED`; an accepted quote can be converted to an `Invoice` (`Invoice.quoteId` records that link; deleting the quote afterward just nulls this field, the invoice survives). `InvoiceStatus` deliberately has **no stored `OVERDUE` value** — it's always derived as `dueDate < now && status !== PAID`, so it can never go stale without a cron job. `Invoice.total` is the final post-discount amount (see `discountType`/`discountValue` — applied to the pre-VAT base, with VAT recomputed on the discounted amount, not a flat cut off the total). Both models share a `Currency` enum (CZK/EUR/USD, no FX conversion anywhere — aggregates are documented as CZK-only) and a `hideItemPrices` flag (default `true`) that switches the PDF/preview into a per-category-subtotal view instead of itemized pricing. `category` on both item types is a **plain string, not a foreign key** — it's matched against `ItemCategory`'s org-wide default list in the UI but a document can freely use a one-off category name that's never saved globally.
- **`Payment`** — one row per recorded payment against an `Invoice`; `Invoice.amountPaid`/`status` are derived from summing these (see `revertInvoicePaidAction` in `lib/actions/finance.ts` for how "undo mark as paid" recomputes from real `Payment` rows rather than just flipping a flag back).
- **`InvoiceEvent`** — a small, targeted action log (created/issued/payment-recorded/marked-paid/reverted) for the invoice detail page's "History" panel. Not a general audit log — that's still out of scope app-wide.
- **`CompanySettings`** — a true singleton (`id: "singleton"`). Holds the company's own profile (name/address/IČO/DIČ/VAT/bank account for the invoice PDF's QR payment code), branding (`logoPath`, `accentColor`), the **app-wide color palette** (`bgColor`/`surfaceColor`/`inkColor`/`accentColor`/`positiveColor`/`warningColor` — injected as CSS custom properties on every page by the root layout, see `theme.ts`), and `locale` (`"en"`/`"cs"`, the whole app's UI language). Edited across Settings' Company and App settings tabs.
- **`Client`** / **`ClientContact`** — a real client company, added going forward only (never auto-backfilled from `Event`'s free-text company fields, to avoid silently merging near-duplicate names). `Client`'s address is **structured** (`street`/`city`/`postCode`/`state`), unlike `Event`'s/`CompanySettings`' single free-text address field — chosen so it round-trips cleanly through the Photon address-autocomplete and the ARES lookup's split-address parsing.
- **`ItemCategory`** — org-wide default line-item categories (seeded: Video/Audio/Rigging/People/Other), editable in Settings → Templates. No FK relationship to `QuoteItem`/`InvoiceItem.category` — deleting a default category never touches items already tagged with it.

**Seeds** (`prisma/seed.ts`, `prisma/seed-empty.ts`) — two different starting states, chosen at will via `npm run seed:demo` / `npm run seed:empty` (or `dev:demo` / `dev:empty` to seed-then-launch in one command):
- **`seed.ts`** ("demo" dataset) wipes every table and creates 4 users (Admin/Accountant/Producer/Member, all password `changeme123`), 4 `Client`s matching 4 demo companies, and 7 `Event`s covering a spread of statuses/scenarios on purpose — e.g. "Autumn Conference" (confirmed, fully fleshed out), "Roadshow" (closed, an overdue follow-up invoice), "Team offsite" (a real example of the discount feature), "Dealer meeting" (a quote still in DRAFT) — plus company overhead expenses, extra time-tracking history, and one live running timer, so every screen in the app has something real to look at. `withTotal()` and `variableSymbol()` near the top are small local helpers for building line-item totals and stripping non-digit characters for the QR variable symbol.
- **`seed-empty.ts`** wipes the same tables (plus `CustomRole`, which `seed.ts` never touches) and leaves a genuinely blank slate: one `admin@eventsystem.cz` login and the 5 default `ItemCategory` rows, nothing else — no events, no `CompanySettings` row (the Company settings form already renders correctly against a null company). This is the state meant for entering real production data through the UI rather than starting from placeholder fixtures.

## 5. Auth (`src/auth.ts`, `src/types/next-auth.d.ts`)

- **`src/auth.ts`** — the entire NextAuth (Auth.js v5) configuration, exporting `handlers`/`signIn`/`signOut`/`auth`. One `Credentials` provider only (no self-registration, no OAuth yet — accounts are admin-issued per the brief). `authorize()` looks the user up by email (including their `customRole`), checks `active`, verifies the password with `bcrypt.compare`, stamps `lastSeenAt`, and returns the shape (`role`, `isCardHolder`, `customRole`) that feeds the session. Session strategy is `jwt`; the `jwt()`/`session()` callbacks copy `id`/`role`/`isCardHolder`/`customRole` from the authorize() result onto the token and then onto `session.user`, so every server component/action can read `session.user.customRole` directly without a fresh DB query. `pages.signIn` points at `/login` (the app's own login screen, not a default NextAuth page). **Where the actual "is this user allowed to do X" logic lives is `src/lib/authz.ts`, not here** — this file only establishes *who* the logged-in user is, not what they can do.
- **`src/types/next-auth.d.ts`** — a small ambient module augmentation adding `id`/`role`/`isCardHolder`/`customRole` to NextAuth's built-in `Session.user`, `User`, and `JWT` types, so `session.user.role` etc. type-checks everywhere instead of being `any`. The route handler that actually wires `auth.ts` into Next's routing is `src/app/api/auth/[...nextauth]/route.ts` — see section 1.

On any host other than Vercel (e.g. Railway), NextAuth also needs `AUTH_TRUST_HOST=true` set as an environment variable — Vercel is the only platform it auto-trusts, and without this it throws `UntrustedHost` behind a reverse proxy.
