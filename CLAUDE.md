# Event system — working notes

Internal web app for an event agency: events from inquiry to invoicing, finance (quotes/invoices/expenses/reports), time tracking. Source of truth for requirements: `docs/system_info/event-system-zadani.pdf` (Czech brief, 17 Aug 2026). Visual/UX source of truth: `docs/wireframes/` (see `docs/wireframes/README.md` for the screen index and decisions already made there — don't re-derive those, they're settled).

Build plan for the current phase lives at `/Users/simonpletka/.claude/plans/tingly-popping-hippo.md`.

**Terminology note (2026-09-02): "Event" was renamed to "Project" throughout the live app** — the Prisma model, every FK/field (`eventId`→`projectId`, `EventMember`→`ProjectMember`, `EventContact`→`ProjectContact`, `MeetingEvent`→`MeetingProject`, `EventsAccess`→`ProjectsAccess`, etc.), routes (`/events`→`/projects`), all UI text/dictionary keys, and file/component names (`EventForm`→`ProjectForm`, `lib/actions/events.ts`→`lib/actions/projects.ts`, etc.). `InvoiceEvent`/`InvoiceEventType` are unaffected — that "event" is an unrelated audit-log-entry concept, not the renamed entity. The history below predates the rename and still says "Event"/"event" throughout (a changelog, left as period-accurate — like git commit messages, not retroactively edited); when it names a specific field/function/route, mentally substitute the Project-era name above rather than trusting the literal string. The Notion integration's *external* database (built before the rename) is still literally named/structured as "Events" in the user's Notion workspace — `NOTION_PROJECTS_DATABASE_ID` is the correctly-renamed env var pointing at it, but the Notion-side property names were deliberately left alone (renaming a live external workspace wasn't in scope).

## Recurring gotchas (read before touching these areas again)

- **RSC serialization boundary**: a Server Component may never pass a plain function to a Client Component prop (`Functions cannot be passed directly to Client Components` — runtime error only, `next build`'s typecheck won't catch it). Hit repeatedly with parameterized dictionary strings (`t.foo.bar(count)`) and closures (`eventHref`). Fix: Client Components take a plain `locale: Locale` prop and call `getDictionary(locale)` themselves — **always from `@/lib/dictionary`, never `@/lib/i18n`** (the latter re-exports a server-only `getLocale()` that imports Prisma → `better-sqlite3`, which drags native Node bindings into the client bundle and fails the build outright, a distinct second-order version of the same bug).
- **Destructive-action confirmation**: never gate a server action behind `<form action={fn}> onSubmit={(e)=>{if(!confirm())e.preventDefault()}}` — this races React 19's internal form-action dispatch and doesn't reliably win. Use a plain `<button type="button" onClick={...}>` that calls `confirm()`/the app's own `ConfirmDialogProvider` synchronously first, then only on approval builds `FormData` and calls the imported action directly inside `startTransition()`.
- **CSS Cascade Layers**: Tailwind v4 utilities live in a layer; hand-written unlayered rules in `globals.css` (e.g. `.btno`, `.heading-label`, `.label`) always beat a same-specificity layered utility regardless of source order. Use the `!` important-modifier on the Tailwind class to win.
- **Dev server**: `pkill -f "next dev"` is unreliable and can leave a stale process silently serving an old build on port 3000 while a new one falls back to 3001. Use `lsof -ti:3000 | xargs kill -9`, then verify with `lsof -i:3000` before trusting what the browser shows. Separately: **a Prisma schema/client regen requires a full dev-server restart** — the in-memory client stays stale even though a fresh `npm run build` (a new process) looks clean.
- **react-pdf font registration**: `@react-pdf/font`'s `FontStore` caches a loaded font under its registered family name for the life of the Node process — registering once at module scope leaks subsetting state across unrelated `renderToBuffer()` calls (reproduced: rendering an invoice then a quote back-to-back corrupted specific digits in the second). Fix: call a `registerAppFont()` fresh inside each PDF component's render body, family name suffixed with a unique id per render.
- **Variable fonts in react-pdf**: fontkit doesn't interpolate a variable font's weight axis per the registered `fontWeight` key — it loads the file at its own default instance regardless, so registering one variable TTF under both 400 and 700 silently produces identical (never actually bold) glyphs. Fix: flatten real static instances (`fonttools varLib.instancer`) and register those. The live web app is unaffected — browsers do interpolate variable fonts correctly, so `next/font/local` still uses the original variable file.
- **Local dates**: never round-trip through `new Date(dateOnlyString)`/`toISOString().slice(0,10)` — both convert through UTC and can roll the date by one day depending on offset. Use the project's `isoDate()`/`parseIsoDate()` helpers (`src/lib/calendar.ts`).
- **Sticky page header** is `src/components/ui/PageHeader.tsx` (was 10 inline copies of the same `sticky top-0 -mx-6 … backdrop-blur` div). Must be a **direct child of the page's `<main>` box** so its content lines up with the page body. The frosted background is a **separate absolutely-positioned layer** at `left-[calc(100%_-_100vw)] w-screen` so the strip spans the whole viewport — *including behind the floating sidebar*, which is raised to `z-30` (above the header's `z-20`) so it floats on top of the strip. Put the page's `max-w-*` on a wrapper *inside* `PageHeader` and on the body — never wrap `PageHeader` itself in a `max-w`/`mx-auto` div (that was the bug that stopped the header spanning full width). `pb` is a prop, not `className` (two `pb-*` in one class list don't resolve by source order — cascade-layer gotcha below).
- **`overflow-x: hidden` on `html`/`body`** silently promotes the computed `overflow-y` to `auto` too (per spec, when only one axis is set to non-`visible`) — this broke the pinned sidebar's `position: sticky` (it now stuck to the wrong scroll container). Use `overflow-x: clip` instead — same visual clipping, doesn't establish a scroll container.
- **PDF mockup-to-page conversion**: the mockup canvas is 794×1123 CSS px = A4 at 96dpi; the PDF page is A4 in points (595.28pt). Every mockup pixel value converts via the literal `pt = px × 0.75` — treat it as an exact unit conversion, not an eyeballed guess, when matching a design mockup in `@react-pdf/renderer`.
- **ARES address**: use the `adresaDorucovaci` object (already split into `radekAdresy1/2/3`), not the flat `sidlo.textovaAdresa` one-line string, when a structured street/city/postCode split is needed.
- **`npm install` blocks postinstall scripts** (npm 11 allow-scripts) — run `npm approve-scripts <pkg>` after adding a dependency that needs one (Prisma, native modules).
- **Scripted-click verification with repeated button labels** (e.g. every list row has its own "Edit"/"Delete"): `document.querySelectorAll('button').find(text match)` returns the *first* DOM match, which is easy to mistake for "the one I meant" — cost a real, permanently-deleted seeded time entry once (had to be manually recreated). Scope the query to the specific row/dialog first (`.closest(...)` from a uniquely-texted leaf node, or a distinguishing class on the target button) before matching by text, especially for anything destructive.

## Data model decisions

- **`Quote.createdById`** (required FK) + **`User.phone`** — "Created by" reuses `issuedAt` as the creation date (already `@default(now())`, never edited).
- **`User.locale`** (nullable, "en"/"cs") overrides `CompanySettings.locale` when set. **`User.avatarPath`** mirrors `CompanySettings.logoPath`. No `firstName`/`lastName` columns — Settings → General splits/rejoins the single `name` field client-side since ~20 call sites already read `name` directly.
- `EventStatus` has the brief's 6 states **plus `CANCELLED`** (brief explicitly invites this).
- Event detail is tabbed (3c), not single-scroll (3d) — explicit user choice.
- **Numbering**: `Event.number` = `YY-XXX`, lowest unused integer per year at creation (reusable after deletion). Quotes/invoices reuse the event's number with `_v2`/`_v3`… suffixes past the first document of that type (`src/lib/document-number.ts`). Not concurrency-safe (no locking) — accepted tradeoff.
- **`EventContact`** (1+/event) syncs onto the linked `Client`'s `ClientContact` list on save — deduped by email-then-name, independent copies (no FK back). `Client.invoicingEmail` auto-fills from the first synced contact with an email, only while still blank.
- **`ItemCategory`** — org-wide defaults, deliberately *not* a FK on `QuoteItem`/`InvoiceItem.category` (plain string) so a one-off category never pollutes the global list and deleting a default never touches already-tagged items.
- **Invoice discounts** (`discountType: NONE|PERCENT|FIXED`, invoice-only) apply pre-VAT, VAT recomputed on the discounted base. `Invoice.total` stores the final post-discount amount.
- **`Quote.subtotal`/`Invoice.subtotal`** (pre-VAT base; an invoice's is post-discount) exist alongside `total` (VAT-inclusive) specifically so "value"/rollup figures can exclude VAT — Czech accounting treats VAT as a pass-through liability, not revenue. The documents themselves (PDF, detail page) still show the full VAT-inclusive `total` as always. The scope line: anything answering "how much is this worth / was invoiced" (`Project.quotedValue`, Client "total charged", Reports income/balance/margin, Quotes "open value", Project Finance tab "Invoiced") reads `subtotal`; anything answering "how much cash is owed/received" (invoice payment tracking — `amountPaid`, overdue totals, "paid this month") keeps reading `total`, since that's real money. Every excl-VAT figure in the UI carries an explicit "(excl. VAT)" label — never bare.
- **`InvoiceStatus` has no stored `OVERDUE`** — derived everywhere as `dueDate < now && status !== PAID`.
- **VAT**: `CompanySettings.isVatPayer` + per-line-item `vatRate` (default 21%).
- **`Currency`** (`CZK|EUR|USD`) on Quote/Invoice; individual documents/PDFs always show their own real billed currency, unconverted. Aggregates that sum across documents (Reports, Dashboard, Client "total charged", Finance KPIs) convert non-CZK amounts to CZK via `src/lib/fx.ts` — the Czech National Bank's daily fixing rate on each document's own `issuedAt` date, free/no-key, with a hardcoded fallback rate if the live fetch fails so a CNB outage never breaks a page. `isMixedCurrencyTotal`'s asterisk note now just flags "this total includes a conversion," not an accuracy caveat. QR payment code still skipped for non-CZK (spec is CZK-only) — unrelated to this.
- **`Client`/`ClientContact`** added going forward only, never backfilled from `Event`'s own free-text company fields (fragile fuzzy-matching risk). `Event.clientId` nullable FK; `Event.companyName/Address/Ico/Dic` untouched and still what PDFs/detail pages read from — `clientId` only powers the Clients section's rollup. `canManageClients()` = `canManageFinance() || canCreateEvent()`, no new permission dimension.
- **`Project.quotedValue` is derived, not manually typed** — originally a free-typed "rough estimate" field on the project form, it drifted from the real Quote/Invoice enough to be actively misleading (a EUR quote's CZK-equivalent could differ wildly from a stale CZK guess), and removed from the form entirely now (no UI shows it as editable). `src/lib/quoted-value.ts`'s `syncQuotedValue()` recomputes and stores it at every quote/invoice create/edit/delete/status-change: **the latest quote's subtotal if that quote is ACCEPTED**; else **the sum of every invoice's subtotal issued for the project**, if there are any (covers a quote declined-but-invoiced-anyway, and a project invoiced with no quote at all); else **0** (a DRAFT/SENT quote alone, or a DECLINED one with nothing invoiced, doesn't count as "the value"). Reads `subtotal` (excl. VAT), not `total` — see the `Quote.subtotal`/`Invoice.subtotal` note above. Converted to CZK via `src/lib/fx.ts` per document when foreign. `BudgetField`'s "% of quoted" mode reads this as a fixed snapshot, since nothing on the project form can change it anymore.
- **Expense "paid by"**: defaults to self; non-card-holders can only submit as themselves; card holders (or Admin/Accountant/Producer) get a dropdown of card holders + self.
- **Company overhead**: `Expense.eventId` nullable, not a fake pseudo-event.
- **Expense VAT**: `Expense.amount` is the gross paid; `Expense.vatRate` (21/12/0) + `Expense.vatAmount` (deductible input VAT, 0 = none reclaimable) are separate — net/excl-VAT expense used by Reports is `amount − vatAmount`. `vatAmount` auto-derives from gross×rate in the form but is editable so a receipt's real rounded VAT lands exactly. No `currency` on `Expense` (still always CZK). Pre-existing rows migrated to `vatRate 21 / vatAmount 0` — no retroactive input-VAT claim until edited.
- **VAT regime is inferred, not stored**: `classifyRegime(dic)` (`src/lib/vat-regime.ts`) reads the customer DIČ prefix — `CZ…` domestic, other EU-member prefix = intra-community reverse charge, else export. No per-invoice override (deferred). Used only by Reports → VAT.
- **`CustomRole`**: four tier enums (Events/Finance/Expenses/Settings access), same granularity as built-ins, not a generic bitmask. `User.role` is never nullable — when `customRoleId` is set, `role` holds an ignored `MEMBER` fallback so a missed call site fails closed, not open.
- **Invoice "History"** (`InvoiceEvent`) is a small targeted action log, not a general audit log.
- **Running timer** = a `TimeEntry` row with `running: true`; "one timer per user" is app-level (start stops any existing one), not a DB constraint. `TimePhase` enum inferred from the wireframe legend (brief doesn't name it).
- **`TimeEntry.eventId` is nullable** — entries can be created unassigned and assigned later via edit. Unassigned entries display via a shared `unassignedEvent` dictionary string and group under one bucket in aggregation queries.
- **Compare Events "cost per hour"** (superseded by Overview) was just `quotedValue ÷ totalHours` — no per-user rate field.
- **"Invite user"** creates the account immediately with a shown-once random password — no email system, matches the brief's "issued credentials" model. No pending-invitation state.
- **`User.lastSeenAt`** updates on login only, not every request.
- **Invoice email templates** live on `CompanySettings` (one shared pair, plain `{{token}}` string replacement — no templating library, the token set is small and fixed).
- **`Meeting`↔`Event` is many-to-many** via the `MeetingEvent` join model (an event can have several meetings; a meeting — especially an internal one — can span several events, or none). Recurrence (`recurrenceFreq`/`recurrenceInterval`/`recurrenceUntil`) is a rule on the row, not materialized per-occurrence rows — deliberate scope cut, no per-occurrence edit/cancel. `Event.notionPageId` is the only place an external id is cached on an app row; everything else about the Notion sync is push-only and stateless.
